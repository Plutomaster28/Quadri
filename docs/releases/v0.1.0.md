# SeaBird SDK v0.1.0 — Foundation Edition

Released: 2026-07-21  
Toolchain status: developer alpha  
Architecture input: SeaBird v3.0-rc2

Official standard-build tag: `tuna`  
License: Apache License 2.0

Today we are officially marking the first SeaBird SDK milestone.

**SeaBird SDK v0.1.0 creates the foundation for our custom ISA and the silicon
built around it to finally stand on.** It is the first coherent, versioned
toolchain baseline: C can become native SeaBird code; assembly can become
ELF objects and hardware-consumable images; binaries can be linked, inspected,
disassembled, archived, and stripped; and the result can be checked against an
executable architectural model.

This release does not claim that the entire operating-system ecosystem or the
eventual chip is finished. It establishes something more fundamental: one
machine-readable ISA, one canonical encoding path, one compiler target, one
ABI direction, and one automated conformance baseline from which hardware and
software can now advance together.

## Stability promise

v0.1 freezes the release's documented input formats and canonical assembly
spellings as a development baseline. It does not yet promise production ABI or
binary compatibility across all future v0.x releases. Any necessary breaking
change will be documented in the changelog and release notes.

The normative architecture specification remains separately versioned as
SeaBird v3.0-rc2. The SDK version describes toolchain maturity; it does not
silently change architectural behavior.

## Toward v0.2

v0.2 will build upward from this foundation rather than restarting it. Its
planned focus is Tritium runtime completion, a minimal packaged C environment,
stronger linking and hardware-image workflows, binary16 lowering, debugging,
and qualification against increasingly independent emulators and silicon.

The detailed implementation boundary is maintained in
[`COMPILER_STATUS.md`](../COMPILER_STATUS.md), with architecture-wide gates in
[`ARCHITECTURE_STATUS.md`](../ARCHITECTURE_STATUS.md). The executed release
gates are recorded in [`v0.1.0-validation.md`](v0.1.0-validation.md).
